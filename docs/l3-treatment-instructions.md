# L3 四段治疗指令

这里的指令 L1–L4 是四段治疗指令，与系统 Layer1–Layer4 不是同一概念。
诊断和疗法决策不变；四段指令是 L4 的治疗决策输入。患者原话、对话历史、L1 安全控制和审核回环仍保留。

## 生成与执行顺序

1. ICD-10 候选与治疗计划经过临床复核后，`InstructionGenerator` 用规则编码会话级 L1、L2、L4；此时 L3 为 `null`，尚不能生成治疗回复。
2. L3 输出校验检查指令与原报告的一致性，现有报告完整性凭证覆盖最终指令。
3. L4 创建会话，只读取报告内的静态指令；不另行构造诊断锚点。
4. 每条新的患者消息先经过原有 L1 安全入口。允许继续时，编排器调用 L3 的 `TurnInstructionPlanner`。
5. L3 调用 API，输入静态指令、历史目标/技术、患者原话、已发送回复、兜底记录及最新安全限制，生成本轮目标、技术、衔接、插件指导和进展观察。
6. 规则校验授权技术/插件、禁忌、技术密度、引用原话、会话/轮次绑定和阶段转换条件。失败则不调用 L4，也不推进会话进展。
7. L4 再执行指令守卫，随后调用生成 API，并沿用 L5 审核/重写。L4 不再依据自己输出的 `stage_complete` 推进阶段。
8. 成功发送后记录本轮指令和对话，供下一轮 L3 使用。兜底回复也记录，但不能作为目标完成证据。

## LLM 和规则分工

| 功能 | 实现位置与方式 |
| --- | --- |
| 会话角色、诊断锚点、防越界指令 | L3 `instructions/instruction_generator.py`，规则编码已知结果 |
| 本轮目标、语义衔接、技术提议、插件嵌入指导 | L3 `instructions/turn_planner.py`，API |
| 患者回应、作业情况、未解决事项解释 | 同上，API；每项解释必须附原话，不将模型解释当作新诊断 |
| 已批准疗法转换为允许技术 | L3 编码规则，不重新匹配疗法 |
| 轮次、证据、技术/插件授权、安全限制、推进条件 | 共享指令守卫；L3 自检，L4 执行前验证 |
| 自然语言回复 | L4 生成 API，只执行指令 |
| 输出审核和重写 | 原有 L5 及回环，策略不变 |

阶段不按轮数自动变化。阶段推进必须有上一目标达成、患者准备好和当前患者原话；每次最多前进一步，可停留或回退。条件来自 L3 的语义判断，规则验证信号和证据绑定，不声称规则能证明临床判断正确。

L1/L2/L4 在同一治疗会话内复用。L3 每轮重新生成，但不要求相邻两轮的目标一定不同：患者仍在同一问题上时可以继续。复核批准的诊断与治疗计划在会话中复用。

认知模式和关键叙述完整保留。只有明确标注的核心信念/触发情境才写入相应专门字段；缺少标注时不擅自认定。量表缺失不填零，Y-BOCS 使用 `Y_BOCS` 正确映射。

## 接口调整

共享模型：`shared/schemas/treatment_instructions.py`。
原 `layers.layer4.schemas.instructions` 保留导入入口，指向同一份定义。

`POST /v1/l4/session` 现在接受：

```json
{
  "session_id": "可选的会话ID",
  "report": {"说明": "包含 instructions 和有效 L3 校验凭证的完整诊断报告"},
  "safety": {"risk_level": 1, "sensitive_topics": [], "flags": []}
}
```

不再接受外部 `role`、`boundary` 覆盖报告指令。旧报告需要重新通过 L3 生成并校验，不能仅补造凭证。

`POST /v1/l4/turn` 保留 `session_id`、`user_message`、`turn`。`turn` 必须是 L3 planner 返回的完整对象，含 `session_id`、`turn_number`、`source_message`、`technique_code`、`evidence` 等绑定字段。手写的旧版 `{goal, technique}` 不再通过执行守卫。

外部同轮重写必须沿用原患者消息和原 L3 指令；不能通过重写替换目标或推进阶段。接口校验失败返回 422。

生产模型配置使用 `L3_INSTRUCTION_MODEL`，未设置时复用 `L3_REASONER_MODEL`，再默认到 `deepseek-chat`。连接复用 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 和现有超时/有限重试设置。L3 不调用插件 API。

## 测试与 Review

专项测试：`tests/test_treatment_instructions.py`。
覆盖静态信息保留、逐轮变化、同轮绑定、API 非法输出与超时、阶段转换、插件授权、禁忌、自由文本禁止动作、凭证完整性及真实编排路径。

自动化测试显式注入受控模型；生产默认使用 API。测试验证工程约束，不证明真实模型的临床有效性。
