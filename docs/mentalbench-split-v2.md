# MentalBench 数据划分与诊断流程评测规范 v2

日期：2026-10-16。适用于整个 L3 诊断流程，包括候选生成、逐候选核对和后续独立验证；数据划分范围不等于某一轮代码修改范围。标准库仍为 DSM-5，系统候选仍为 D001–D023＋Insomnia。

## 第3点 分组与实验含义

保留 KB／DEV／EVAL 三部分和目标比例 5∶2∶3，随机种子为 20261015。KB 用于诊断时的参考示例，DEV 用于修改系统，EVAL 用于冻结后的独立评测。当前系统尚未接入案例检索；划出 KB 不代表接入已经完成。

本版本明确选择**按无序障碍组合留出的严格泛化实验**。同一个单障碍 source_code 或无序障碍对的全部记录只能分配给一个部分。92 个不可分单元为：23 个单障碍组、51 个单方向障碍对组、18 个正反双方向障碍对组。

这项选择考察“未在示例池和开发中出现的鉴别组合”上的表现，不声称只要两个独立病例属于同一疾病或鉴别对就必然发生泄漏。相同病例、生成种子及其改写跨部分是需要避免的来源污染；跨病例复用相同诊断知识本身是案例知识库的预期用途。

`related_case_group` 仅是当前可核验的来源编号关系，不等同于真实患者身份，也不能证明所有生成种子已独立。所有数量分别称为记录数、来源组数、超级组数。来源组数不能直接当成统计学有效样本量。

分配槽位：单障碍 11／5／7；单方向障碍对 24／10／17；双方向障碍对 10／3／5。由固定种子的确定性搜索满足各部分 23 标签覆盖，禁止根据诊断模型表现选择分配。隔离前记录数为 12,375／4,725／7,650；整组约束导致与精确比例有小幅差异。

实现：`tools/mentalbench_partition.py`。

## 第4点 隔离规则与记录归属

先按来源组分配所有记录，再做输入筛查，不把 DEV/EVAL 的坏记录搬进 KB，也不拆散其来源组。每条记录有一个且只有一个分区归属，另有“活动／隔离”状态。总账 = KB活动＋KB隔离＋DEV活动＋DEV隔离＋EVAL活动＋EVAL隔离，必须等于 24,750；各分区活动数不是原始分配数。

规则分为三类：

- **所有部分都隔离**：空占位、过短碎片、英文病例中的中英破损残留。KB 也不允许自动收录这些记录。规则属于可复现的质量筛查，不冒充临床正确性审核；人工确认可读后必须另发新版本才能恢复。
- **仅盲测输入隔离**：正文明确给出当前诊断结论。内容完整时可作为带标签 KB 示例；若已归属 DEV/EVAL，则留在所属分区的隔离区，不能迁移。
- **仅记录待核对标记**：出现病名、既往诊断、否定病史、临床语气，不据此自动认定泄漏。输入中的自然病史事实保持原样，不为匹配规则删除原文。

EVAL 的隔离病例、来源元数据和答案与其 gold 一起封存；不输出所有人可读的完整 EVAL `quarantine.jsonl`。公共报告只含汇总数量和规则，KB/DEV 可见其自己的隔离清单。隔离记录永不进入检索索引或评分输入。

实现：`tools/mentalbench_quality.py`。所有规则在模型评测前固定。

## 第5点 整个 L3 的分阶段指标

`tools/evaluate_candidate_predictions.py` 兼容单独的 candidates 输出和完整 L3 report。单标签参考任务与 Type 3 的 admissible_candidates 分开报告，混合输入不再给出一个可被误读成统一诊断效果的总体 PPV/召回。

- Step 1：严格标注匹配的 micro PPV/召回、Top-K 召回和命中、空候选比例、按标签 precision/recall/F1 和 macro。macro 对有金标准支持的标签求平均；未预测该标签时其 macro precision 取 0。
- 历史 Step 2：仅对旧报告中的独立排除结果统计误排除率并报告分母。当前流程已移除重复 ELIMINATIVE 调用，`checked[].source=step1_tree_records` 表示复用 Step 1，不计作独立 Step 2；相应评测分母为零、误排除率为 null。
- 最终结果：仅对单一参考标签任务报告命中和集合 exact match。Type 3 不作为确诊共病或唯一最终诊断的标准。
- MentalBench 标签覆盖的分母为 23；系统范围仍为 24。Insomnia 没有参考样本，召回为不适用。若模型输出 Insomnia，继续保留在严格标注 PPV 的预测数中，并单独计数，不能静默删掉，也不能据此证明临床上不存在该病。
- 分开报告记录、来源组、超级组数量，不宣称某个数量就是统计有效样本量。严格组外实验以超级组聚类 bootstrap 为主要区间，同时提供来源组聚类敏感性区间；默认 1,000 次，种子 20261015。

所有分数均指相对于数据集参考标签的研究指标；合成数据的标签完整性和临床外部有效性限制仍然存在。

## 第6点 封存、实验冻结与验收

准备脚本为 `tools/prepare_mentalbench_split.py`；正式评测控制为 `tools/mentalbench_eval_protocol.py`。默认新目录为 `artifacts/datasets/mentalbench_split_v2`，已存在时拒绝覆盖。原始仓库、原始适配文件和原 Word 要求均不覆盖。

输出角色如下：

| 位置 | 内容及用途 |
|---|---|
| `engine/{kb,dev,eval}.inputs.jsonl` | 仅 `case_id` 与 `profile`，作为引擎输入；没有 gold、选项或来源疾病目录元数据 |
| `development/{kb,dev}.gold.jsonl` | KB/DEV 独立答案文件，开发与构建示例池时使用；不可直接并入患者画像 |
| `development/{kb,dev}.quarantine.jsonl` | KB/DEV 的隔离记录、理由和原分区归属 |
| `sealed/eval.bundle.dpapi` | EVAL 活动 gold、隔离病例及其答案、分组信息的加密封存包 |
| `split_report.json`、`integrity.json` | 汇总验收和本版本输出完整性校验；不公布 EVAL 个案答案 |
| `protocol.draft.json` | 待确定实验配置的草稿，不能直接开启评分 |

使用 Windows CurrentUser DPAPI，不写出明文 EVAL gold 或 EVAL 隔离清单，也无明文降级路径。它保护本版本答案文件的日常存放，**同一 Windows 账户仍可解密**；严格的评测人员隔离需要独立评测账户。原始公开数据及旧的全量 gold 仍存在，封存不能消除研究者或模型之前的接触，也不能保证基础模型预训练未见过公开数据。

正式运行前，需在草稿中列出全部比较方案，包括推理模型与明确版本、验证/奖励模型与版本、提示词版本、树版本、检索策略、解码等参数；不接受空实验列表或 `latest/default/TODO` 代替版本。暂未接入自研奖励模型时，不得填成已接入；未来比较方案需如实登记。`input_condition` 必须区分叙述输入与核对后的结构化画像。

冻结时保存实际工作区代码和知识 JSON 快照、冻结协议及校验值，而非仅记录无法代表未提交修改的 Git HEAD。正式预测应来自该快照与协议；评分工具核对运行声明，但不能凭声明证明外部模型服务实际执行了对应版本，运行方仍需保存实际 API 版本和日志。

一次正式评测可以包含**全部预先登记的对照和消融方案**。统一提交各方案的完整 EVAL 预测，先核对方案集合、声明配置、数据完整性及案例覆盖，再预留一次性评分状态，之后才读取封存答案。缺失案例不允许静默丢弃；成功或开封后的评分失败均不允许自动换一批预测再试。发现污染时记录理由并作废版本。

仅改变随机种子不能恢复独立性。如果之前已使用某组进行检索、调试或查看结果，新 EVAL 必须避开这些已接触组；没有足够未接触组时需要新数据。当前脚本不提供跨版本的自动接触史证明，因此 v2 不被宣称为已确认从未接触的正式临床留出集。

命令均在 `L1-L5系统` 目录运行：

```powershell
# 准备新版本；本次已执行，重复执行默认拒绝覆盖。
.\.venv\Scripts\python.exe tools/prepare_mentalbench_split.py

# 配置全部明确后才冻结；本次未执行。
.\.venv\Scripts\python.exe tools/mentalbench_eval_protocol.py freeze artifacts/datasets/mentalbench_split_v2 --protocol artifacts/datasets/mentalbench_split_v2/protocol.draft.json

# 完成所有预登记方案的预测后统一评分；本次未执行。
.\.venv\Scripts\python.exe tools/mentalbench_eval_protocol.py score artifacts/datasets/mentalbench_split_v2 --runs <runs.json>
```

`runs.json` 按实验 ID 对应预测文件和冻结配置，结构如下；字段值须来自冻结协议，不能照抄占位文字：

```json
{
  "实验ID": {
    "predictions": "该实验完整预测JSONL路径",
    "declared_experiment": {"与冻结协议中该实验完全一致的配置": "此处仅示意"},
    "code_snapshot_sha256": "冻结快照校验值"
  }
}
```

预测行可为 `{"case_id":"...","report":{完整L3报告}}`，也兼容只有 `candidates` 的候选实验；只提供候选时不会凭空生成 Step 2 和最终结果指标。

案例 ID、source_code、来源组及无序障碍组合均无跨分区重叠；分区总账、活动/隔离互斥、23 标签覆盖、三个生成模型比例平衡和封存往返检查通过。DEV/EVAL 各任务类型的最大比例差为 2.18 个百分点，低于预先设定的 3 个百分点限值。

本版隔离数是新筛查规则的实际结果，取代旧方案的示意数量。规则检查通过不等于每条病例已被专家审核。系统测试 **472 passed**，包括 16 项本轮新增分组、筛查、分层指标和封存流程测试；测试评分使用临时人工夹具，不是正式 EVAL。
